# 受付Bot：発見から継続利用までの改善仕様

日付：2026-09-23 / 対象ベース：0f94710 / 目的：長期売上につながる、実際に受付を始められる利用者を増やす。

## 方針
登録数だけでなく、Bot公開→設置・共有→実際の回答→有料継続を成功とする。現行価格・30日Light無料・カード不要・明示契約なしの自動課金禁止・生成AI非依存は変えない。架空の導入数や効果保証は使わない。今回のリリースで売上増加そのものを実証したとは言わない。

## 全体レビューによる優先順位
P0：登録前の理解不足（動くデモなし）、作成後の基本情報訂正不可、必須会社名と入力画面の不一致、質問保存前のプレビュー離脱、公開・設置の説明不足、回答の自動送信と修正経路、無料体験期限の信頼できない入力源。
P1：検索される自社ページの不足、title/canonical/sitemap/noindex不足、登録時の用途の消失、空の管理画面、期限後の挙動が不明、回答一覧が無制限取得。

## 採用する設計
- 「問い合わせの聞き直しを減らす、会話形式の受付フォーム」と説明。AIが自由に回答する商品ではないと明示。
- 登録前に保存・送信しない本物のChatFormデモを試し、選択した業種・目的を登録後の作成へ渡す。
- 用途別は士業、不動産、採用の3つに絞り、質問例・設置方法・扱わない用途を具体化。大量の薄い検索ページは作らない。
- 会社名・Bot名・通知先を明確にし、任意設定は後から。作成→質問確認→公開→URL共有を主経路とし、HTML埋め込みは任意。
- 保存前/保存済み、動作確認/実送信を分離。通信失敗から同じ下書きを復帰できるようにする。
- 回答者には最終確認・編集・明示送信を用意。入力失敗や送信失敗で回答を失わない。
- 無料体験はSupabase Authの管理されたアカウント作成日時から判定し、利用者が編集できるprofiles.created_atは使わない。
- 管理画面は実際のBot状態から「次の一手」を表示。共有を完了したと推測しない。
- 公開マーケティングページは認証通信を不要とする。顧客の公開フォームを自社SEO目的で索引に載せない。

## 必要な検証
1. 新規利用者：デモ→選んだテンプレートで登録→下書き作成→編集保存→動作確認→公開→別セッションから回答確認/修正/送信→一覧反映。
2. 無料体験：登録日時が改変できないこと、正確な30日境界、未来/無効値拒否、有料優先、無契約の自動課金なし、既存無料/有料契約の回帰。
3. 初心者の回復：必須情報未入力、質問保存の失敗、コピー失敗、送信失敗、同じボタンの連打、入力変換中のEnter。
4. 360px・390px・768px・1440px、横溢れ、タップ領域、ラベル、キーボード、ステータス通知、入力中データ維持。
5. 公開ページの200/title/description/canonical/リンク/sitemap/robots、顧客フォーム・管理画面のnoindex、認証はnoindexとは別に必須。
6. npm test / lint / typecheck / buildと本番の実表示・主要E2E。決済の再課金は行わない。

## 成果測定
公開・回答受信・契約は既存DB/Stripeで確認できる。指標は登録→初回Bot作成→公開→初回回答→有料継続、および初回公開に要した時間。トップ・料金・デモ・業種別ページ・ガイドの流入・参照元・端末傾向はVercel Web Analytics、Core Web VitalsはSpeed Insightsで確認する。管理画面・顧客の公開/埋め込みフォームは計測対象外とし、回答本文をAnalyticsのカスタムイベントへ送信しない。検索の表示回数・クリックは所有者のSearch Consoleで観測する。順位・転換率・売上の改善は実ユーザーの計測後に評価し、リリース時の推測を実績にしない。
